# mail_backup — резервное копирование, перенос и восстановление почты по IMAP

Веб-сервис на FastAPI поверх `imapsync`: бэкап почтовых ящиков на отдельный диск
сервера, восстановление из бэкапа, прямой перенос между хостерами, графики.

## Правила работы над проектом

- **Все комментарии и docstring в коде — на русском.**
- **Всё о проекте (решения, архитектура, статус этапов) фиксировать в этом файле.**
- Python в venv, установка прямо в систему (без Docker).
- Вся работа ведётся через git: основная ветка `main`, каждый этап/задача —
  отдельная ветка, коммиты с осмысленными сообщениями на русском.
  Секреты, `.env`, `var/` и `.venv/` в репозиторий не попадают (см. `.gitignore`).

## Требования и принятые решения

| Тема | Решение |
|---|---|
| Сервер | Ubuntu 26.04, прямая установка, Python ≥ 3.12 в venv |
| Стек | FastAPI + SQLAlchemy 2 + SQLite (WAL), Jinja2 + HTMX + Chart.js |
| Ящики | ~10 штук |
| Хостеры | Яндекс, Mail.ru, любой IMAP вручную (пресет `custom`) |
| Движок | `imapsync` **2.314** (из GitHub по тегу `imapsync-2.314`, в репозиториях Ubuntu его нет) |
| Хранилище | Локальный Dovecot, Maildir на **отдельном диске** (`MB_BACKUP_ROOT`) |
| Снимки и выгрузка | **restic**: локальный репозиторий на том же диске + копии на другие серверы (SFTP) |
| Админка | Один администратор, логин + argon2-хеш в таблице `settings` |
| Уведомления | Не нужны |
| Срок хранения | Вариант «Б»: снимки restic старше `retention_days` удаляются (0 = бессрочно) |

### Хостер — только чтение (жёсткое требование)

При бэкапе на хостере **ничего не менять**: не удалять, не перемещать,
не помечать прочитанным. Письма копируются со всеми флагами и датами.

- imapsync меняет host1 только с флагами `--delete1`, `--expunge1`,
  `--delete1emptyfolders` — сборщик команды обязан их отклонять для бэкапа.
- Явно передавать `--noexpunge1`.
- Флаги (`--resyncflags`) и даты (`--syncinternaldates`) переносятся по умолчанию;
  imapsync сохраняет непрочитанные письма непрочитанными.
- imapsync читает host1 через `Peek(1)` (проверено по исходнику) — \Seen не ставится.
- Защита в коде: `mail_backup/imapsync/command.py::check_safe` отказывает в запуске
  при флагах изменения host1, а при восстановлении/переносе — и при флагах удаления на host2.

### Срок хранения (вариант «Б») и restic

- Maildir в Dovecot — **зеркало** ящика: бэкап идёт с `--delete2 --delete2folders`,
  удалённое на хостере удаляется и из зеркала (это касается только нашего диска).
- История хранится в снимках **restic** (по снимку на ящик, тег `mailbox-<id>`):
  после каждого бэкапа — `restic backup`, затем `restic forget --keep-within <N>d --prune`.
  Удалённое на хостере письмо можно восстановить из снимка в пределах N дней.
- Выгрузка на другие серверы — `restic copy` в удалённые репозитории (SFTP), этап 6.
- Восстановление из снимка: снимок распаковывается во временную учётку Dovecot,
  оттуда imapsync копирует в целевой ящик (этап 6).

## Архитектура

```
хостер ──imapsync──▶ локальный Dovecot (Maildir на отдельном диске)   = бэкап
локальный Dovecot ──imapsync──▶ любой ящик                            = восстановление
хостер A ──imapsync──▶ хостер B                                       = перенос
```

- Для каждого ящика в локальном Dovecot заводится своя учётка
  (`Mailbox.local_login` / `local_password_enc`). Dovecot слушает только 127.0.0.1:143.
- Веб (uvicorn) и воркер — два systemd-сервиса, общая SQLite в режиме WAL.
- Пароли ящиков в БД шифруются Fernet; ключи — в `MB_SECRETS_DIR` (права 600).
- В imapsync пароли передаются через `--passfile1/--passfile2`, не в командной строке.
- Статистика каждого запуска (письма, байты, ошибки, размеры ящиков) пишется
  в таблицу `runs` и служит источником для графиков.

## Структура

```
mail_backup/
  config.py     — настройки из env (префикс MB_), пути к данным/бэкапам/ключам
  crypto.py     — Fernet-шифрование паролей, создание файлов ключей
  db.py         — SQLite-движок, сессии, create_tables()
  models.py     — Mailbox, Run (запуски imapsync + статистика), Setting
  providers.py  — пресеты хостеров (yandex, mailru, custom)
  auth.py       — пароль единственного админа
  dovecot.py    — учётки ящиков в локальном Dovecot (passwd-file, {SSHA512})
  jobs.py       — выполнение Run: endpoints, запуск imapsync, запись статистики
  imapsync/
    command.py  — сборка команды imapsync + проверка безопасности флагов
    parser.py   — разбор прогресса (ETA) и итоговой статистики, коды выхода
    runner.py   — запуск процесса, лог, файлы паролей (удаляются после запуска)
  main.py       — FastAPI-приложение
  cli.py        — команды CLI (см. ниже)
deploy/
  INSTALL.md           — ручная установка на Ubuntu 26.04 + чек-лист проверки этапов
  dovecot/dovecot.conf — шаблон конфига Dovecot 2.4 (плейсхолдеры @...@)
tests/          — pytest; imapsync подменяется фальшивым скриптом,
                  образец вывода — tests/data/imapsync_output.txt
```

## Настройки (переменные окружения)

Сервер: `/etc/mail_backup/mail_backup.env`; разработка: `.env` в корне проекта
(см. `.env.example`). `.env` ищется по абсолютному пути от корня проекта, а не от
текущего каталога — CLI на сервере запускается через `sudo -u mailbackup` откуда угодно.

## Деплой и проверка

Пользователь деплоит на свой хост и тестирует **поэтапно**; после каждого этапа
всё сливается в `main`. Порядок установки и чек-лист проверки — `deploy/INSTALL.md`
(держать в актуальном состоянии при каждом этапе). Пути на сервере: код `/opt/mail_backup`,
данные `/var/lib/mail_backup`, бэкапы `/srv/mail_backup`, секреты `/etc/mail_backup`,
пользователь сервиса `mailbackup`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MB_DATA_DIR` | `/var/lib/mail_backup` | БД, логи imapsync, tmp |
| `MB_BACKUP_ROOT` | `/srv/mail_backup` | точка монтирования диска с бэкапами |
| `MB_SECRETS_DIR` | `/etc/mail_backup` | `secret.key`, `session.key` |
| `MB_LOCAL_IMAP_HOST/PORT` | `127.0.0.1` / `143` | локальный Dovecot |
| `MB_IMAPSYNC_BIN` | `imapsync` | путь к imapsync |
| `MB_MAX_PARALLEL_JOBS` | `2` | одновременных запусков imapsync |

## Формат вывода imapsync (сверено с исходником)

- Прогресс: `... ETA: <дата>  <сек> s  <осталось>/<всего> msgs left`.
- Итог: блок `++++ Statistics` (`Transfer time : N sec`, `Messages transferred : N`,
  `Total bytes transferred : N (...)`, ...), строка `Detected N errors`.
- Размеры ящиков `Host1/Host2 Nb messages`, `Total size` печатаются в начале и в конце —
  берём последние значения.
- Коды выхода: 0 — успех, 111 — завершён с ошибками по письмам (статус `warning`),
  остальное — сбой (10 соединение, 12 TLS, 16 авторизация и т.д.).

## CLI

```
mail-backup init                         каталоги, ключи, БД
mail-backup set-admin <логин>            пароль админа
mail-backup check                        настройки и версия imapsync
mail-backup mailbox-add <логин> --provider yandex|mailru|custom [--host ...]
mail-backup mailbox-list
mail-backup backup <id> [--check|--dry]  бэкап сейчас (--check: только вход)
mail-backup dovecot-sync                 пересобрать учётки Dovecot
```

## Разработка

```bash

cp .env.example .env

```

## Этапы

1. ✅ **Каркас**: конфиг, БД, модели, шифрование, пресеты, CLI, тесты.
2. ✅ **Обёртка imapsync**: сборка команды (с защитой host1), запуск,
   разбор прогресса и итоговой статистики, учётки Dovecot, шаблон конфига 2.4.
   Не проверено вживую (на Mac нет imapsync/Dovecot) — проверить на сервере.
3. ⬜ **Воркер**: очередь задач, расписание (cron), лимит параллельности, логи.
4. ⬜ **Админка**: вход, CRUD ящиков, проверка подключения (`--justlogin`),
   ручной запуск, логи, мастер восстановления/переноса с `--dry`.
5. ⬜ **Графики**: объёмы по дням и ящикам, размер ящиков во времени,
   длительность и ошибки, живой прогресс, статус последнего бэкапа.
6. ⬜ **restic**: снимки после бэкапа, срок хранения, копии на другие серверы,
   восстановление из снимка на выбранную дату.
7. ⬜ **Деплой**: скрипт установки, systemd, nginx + TLS, бэкап самой БД.
